    Why build it, and what it is not

    Git Extensions works, but it was designed before worktrees were common and long before agents started creating them for you. Diffract aims to replace it completely.

    Goals for v1

    • A modern, fast Windows app you enjoy looking at all day.
    • Worktrees as a first-class concept: see every one, its state and who is using it.
    • Find and safely clean up agent leftovers from Claude Code and Copilot.
    • A full daily driver: commit, merge, interactive rebase and conflict resolution.
    • Repo setup made visible: line endings, default branch, identity, and where each value comes from.
    • Never lose work. Every destructive action has a preview and an undo path.

    Not in v1

    • macOS and Linux. It’s a personal tool for Windows.
    • Hosting integration (PRs, issues, reviews).
    • Plugin system.
    • Reimplementing git. Diffract only drives the git CLI.

    Architecture

    Tauri gives a small native shell around WebView2. The git work stays in C#, running as a sidecar process the shell starts and talks to over stdin and stdout.

    Why keep .NET with Tauri. Tauri’s native side is Rust, but your strength and the hardest logic, parsing and rules, stay in C#. Rust stays thin enough that agents can write most of it.

    Stdio, not localhost. The sidecar never listens on a port, so there is nothing for other processes to connect to and no firewall prompts.

    Live by default. Agents change repos while you look at them. The watcher pushes events so every view stays current, including during a rebase.

    How agent leftovers are detected

    Each rule produces an item with a verdict. Anything in use is never offered for cleanup. Agent patterns live in diffract.json, seeded for Claude Code and GitHub Copilot.

    LeftoverHow it’s foundDefault verdict
    Worktree whose folder is gonegit worktree list --porcelain reports prunableSafe to remove
    Worktree on a merged branchgit branch --merged main plus a clean status in that worktreeSafe to remove
    Stale agent worktreeBranch or folder matches an agent pattern, no commits or file changes for N daysNeeds review
    Local agent branchesgit for-each-ref refs/heads/ filtered by agent patternsSafe if merged, otherwise Review
    Copilot branches from originRemote-tracking copilot/* branches after fetch, checked against mainSafe if merged, otherwise Review
    Stashes left by toolsgit stash list with message patterns like “autostash”Needs review
    Checkpoint refsgit for-each-ref outside heads, tags, remotes and stashSafe if reachable from a branch
    Orphaned commitsgit fsck --unreachable --no-reflogs limited to recent reflog entriesNeeds review
    Old backup tagsTags under archive/ created by Diffract, older than a configurable age (30 days by default)Needs review
    Active workWorktree lock file, or file changes in the last 10 minutesIn use, never cleaned

    The exact branch and folder names both agents use get verified against your real repos in milestone 1, before any rule ships.

    Rebase and conflicts

    The part most Git UIs get wrong. These are the design rules behind the Rebase and Conflicts tabs in the prototype.

    Plain names instead of ours and theirs

    During a rebase git swaps the meaning of ours and theirs. Diffract always labels sides by what they are, like “On main” and “Your commit c4d0a17”.

    Read conflicts from the index

    Conflict sides come from git’s index stages (base, ours, theirs), not from parsing markers in the file. That also handles delete versus modify, renames and binary files.

    Always show where you are

    A banner with the operation, the commit being applied and progress, plus abort and skip that are always one click away. Works the same for merge, rebase and cherry-pick.

    Survives restarts

    State is read from .git (rebase-merge, MERGE_HEAD), so Diffract picks up a rebase started in the terminal or by an agent, and vice versa.

    Core model

    A snapshot of the repo, rules that read it, and sessions for operations that span several steps. Rules are pure functions, so they’re trivial to test.

    public sealed record RepoSnapshot(
    IReadOnlyList<WorktreeInfo> Worktrees,
    IReadOnlyList<BranchInfo> Branches,
    IReadOnlyList<StashInfo> Stashes,
    IReadOnlyList<RefInfo> OtherRefs,
    OperationState? InProgress,   // rebase, merge, cherry-pick
    DateTimeOffset TakenAt);

public sealed record Leftover(
    LeftoverKind Kind, string Name, string? Agent,
    Verdict Verdict, int CommitsAtRisk, string Reason);

public interface ILeftoverRule
{
    IEnumerable<Leftover> Evaluate(RepoSnapshot repo, DiffractConfig config);
}

public sealed record ConflictFile(
    string Path, ConflictKind Kind,   // Content, DeleteModify, Rename, Binary
    IReadOnlyList<ConflictHunk> Hunks);

public sealed record ConflictHunk(
    int Index, string? Base, string Target, string Incoming,
    Resolution? Chosen);

// Destructive work is always plan, then apply
CleanupPlan plan = cleanup.Plan(selected);
await cleanup.ApplyAsync(plan, ct);

    Snapshot, not live objects. One immutable snapshot per refresh. The UI diffs snapshots to animate what changed.

    InProgress drives the banner. If a rebase or merge is underway, every view knows, and the Conflicts tab opens on its own.

    Target and Incoming, not ours and theirs. The session maps git’s stages to these names once, so the UI never has to think about the rebase swap.

    Agent is a guess, not a fact. It comes from patterns in config, so it’s shown as a hint and never used to decide what to delete.

      Console app that builds a RepoSnapshot and prints classified leftovers. Fixture script, rule tests, and a check of what Claude Code and Copilot really leave behind.

      Done when an installed build runs on your machine and updates live.

    3. 3

      Safe cleanup

      1 to 2 weeks

      Cleanup planner, confirm dialog, backup tags for unmerged work, cleanup of old backup tags, operation log with undo.

      Done when you stop cleaning worktrees by hand.

    4. 4

      Done when it stays smooth on a repo with 50k commits.

    Risks

    What could hurt, and how the plan handles it.

    Deleting someone’s work

    Plan then apply, backup tags for unmerged commits, an undo log, and nothing in use is ever offered.

    Getting a rebase wrong

    Diffract drives git’s own rebase and never rewrites history itself. Abort is always available and the fixture suite covers mid-rebase restarts.

    Sidecar packaging

    One win-x64 binary that Tauri bundles. Small, but a step to get working early, not late.

    Windows path quirks

    Long paths, mixed separators, junctions and case-insensitive names. Covered by fixture repos created in awkward folders.

    Scope

    v1 is now large. The checkpoint after milestone 5 means a long tail on rebase never blocks you from using the tool.
